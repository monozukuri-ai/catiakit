# CFV2コンテナの読み取り範囲

コンテナ検査は、NIST CATPartで観測した外側ディレクトリと、所有ストリーム先頭にある入れ子ディレクトリを対象とする。汎用OLE/CFBとしては扱わない。ここで示す制約は現在の受理条件であり、CATIA全形式の仕様ではない。

フィールド配置の参考資料はcadmpegの[Container layout §3](https://github.com/cadmpeg/cadmpeg/blob/6289a0d31901aae9445fb99c4bbf7c8effd1d3f1/docs/formats/catia.md#3-container-layout)。採用コミットは`6289a0d31901aae9445fb99c4bbf7c8effd1d3f1`。資料はcadmpeg contributorsによる[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)で提供される。本実装はその配置情報を参考に独立して作成し、下記の所有範囲制約、未知領域の保持、リソース制限を追加した。cadmpegの実行や参照出力はコアの依存に含めない。

## 外側ヘッダーとディレクトリ

| 位置 | 表現 | 受理条件・意味 |
| --- | --- | --- |
| `0..8` | bytes | `V5_CFV2\0` |
| `8..12` | u32 BE | ディレクトリのファイルオフセット。64以上 |
| `12..16` | u32 BE | ディレクトリ長。オフセットとの和が入力全長に一致 |
| `16..64` | raw bytes | 意味を固定せず`raw_outer_header_tail_hex`として保持 |
| ディレクトリ先頭16 bytes | bytes | `CATIA_V5 CB0001\0` |
| ディレクトリ末尾8 bytes | bytes | `CB__END\0` |

ディレクトリを上限内で借用し、先頭と末尾を検証した上でdescriptorの自己整合性を調べる。解読した範囲以外は`opaque_ranges`として位置と長さを残す。未知領域があればコンテナのcoverageは`partial`。元の入力バイト列は呼び出し側で保持する。

## Descriptorとextent

descriptor先頭を`ds`とし、固定ヘッダー84 bytesを全て`raw_header_hex`に保持する。

| 相対位置 | 表現 | 意味 |
| --- | --- | --- |
| `ds+12` | u32 BE | 論理ストリーム長 |
| `ds+80` | u32 BE | extent数 |
| `ds+84`以降 | 20 bytes × count | extent列 |

extentの5語は全てu32 BE。順に物理オフセット、物理長、論理長、論理オフセット、意味未確定の末尾語。物理オフセットの基準は、外側ではファイル先頭、内側では内側ヘッダー先頭。基準からの値と絶対ファイル範囲の両方を公開する。

受理するextentは長さが非0、物理長と論理長が一致し、列挙順の論理オフセットが0から連続し、合計が宣言したストリーム長に一致するもの。物理範囲はそのコンテナのヘッダー後から自身のディレクトリ前までに収まり、同じストリーム内で重複しない。物理順序は論理順序と異なってよい。異なるストリームのaliasは保持する。名前付きdescriptorの不整合は拒否する。名前文法も構造も受理できない候補は未知領域として残す。

末尾語は全て0なら`zero`、各descriptor内で1からの連番なら`ordinal`、それ以外は`unknown`。生の値を保持し、未知の値は警告する。末尾語を使って並べ替えや変換を行わない。ordinalの確認はsynthetic fixtureによるもので、現行NISTコーパスではzeroだけを観測した。

## 名前と未確定宣言

受理する名前は、descriptor直前の3個の0 byteに先行する、3文字以上の印字可能ASCIIをUTF-16LEで記録した連続列。または`ds+16..ds+80`内の同じ文字列と、終端以後の0埋めによるinline形。後者はsynthetic fixtureで確認した参考資料上の形で、実ファイルでの対応範囲は未確認。

ASCII列の直前のu16 LEが制御値または長さに整合する場合にprefix名を採用する。非ASCII文字の後のASCII接尾辞だけを名前と誤認しないための追加条件である。名前を解読できなくてもextentが完全に整合するdescriptorは、`name: null`と警告を伴って保持する。名前を含む未解明領域は`opaque_ranges`に残る。観測した名前を推測で修正しない。

同名のdescriptorを統合しない。`id`は入力中の列挙順に割り当て、ディレクトリIDとdescriptorの絶対位置を併記する。

prefix名を持つ長さ0・extent数0の宣言は、通常のストリームとして受理せず`unadmitted_descriptors`に保存する。NISTの各CATPartで1件ずつ存在するが、空ストリームや削除済み項目といった意味は未確定。宣言の名前、位置、ヘッダー、理由コードを保持する。

## 入れ子と保存レイアウト

入れ子候補は、受理したストリームの論理先頭8 bytesが`V5_CFV2\0`である場合に限る。ファイル全体のマーカー走査は行わない。外側ヘッダー内、ディレクトリ内、所有されない範囲、ストリーム途中のマーカーは候補にならない。

現在受理する内側ヘッダーは16 bytesで、`+8`と`+12`のu32 BEがディレクトリの相対位置と長さを表す。ヘッダーから内側ディレクトリ末尾までが所有ストリームの最初の物理extent内に収まる場合に解析する。内側extentは内側ヘッダー後から内側ディレクトリ前までに制限する。所有ストリームID、深さ、基準位置を記録し、同じ位置を複数ストリームが指す場合は所有者を追加して一度だけ解析する。

署名やディレクトリが複数extentに分かれる配置は`container.nested_storage_unsupported`として報告し、外側情報を保持する。署名が先頭extentをまたぐ場合も判定する。先頭以外に埋め込まれたコンテナや未解明の包み方は自動検出しない。所有範囲内の内側ディレクトリの破損は入力拒否となり、それ以前の外側証拠は残す。拒否した入力からの抽出は行わない。

`layout`は`outer_directory`、`nested_directories`、`unknown`の構造分類。幾何の`standard_nested`、E5等の保存形式は未判定で、`container.geometry_layout_unclassified`を返す。幾何文法の確認は幾何の復号で行う。

## 制限と再構成

入力全体、1回の借用読み取り、ディレクトリ長、ストリーム数、extent総数、1ストリーム長、論理長総和、深さ、走査仕事量、名前長に上限を設ける。論理長総和にはaliasと内側ストリームも含める。走査仕事量は候補位置・名前の後方走査・extent行を数える。制限超過は破損と区別した診断で停止する。

`reconstruct_stream`は公開メタデータの変更・デシリアライズを考慮して範囲、重複、論理連続性、長さ、再構成上限を再検証する。元の検査と同じ入力を渡す必要がある。高水準の`extract_stream*`は一度読み込んだ同じ入力を検査と再構成に使用する。
